# 日本語の man ページを groff で読みやすくする

確認した環境: Ubuntu 24.04、groff 1.23.0、man-db、Sphinx 9.1 / docutils 0.22。

## このスキルの使い方

Claude Code での呼び出し方:

- `/man-ja` と入力する(続けて用件を書ける。例: `/man-ja document/eyedrop.rst から man ページを作って`)
- または「man-ja スキルを使って」と名前を書いて頼む
- 名前を書かなくても、「日本語の man ページが崩れる」「日本語の man ページを作って」
  「rst の Inline literal の警告が出る」のような依頼なら Claude が自分で使うことがある(確実にしたいときは名前を書く)

スクリプトは Claude を介さずに単独でも使える(下の「対策」を参照)。

```sh
~/.claude/skills/man-ja/fix_man_ja.py page.1
```

置き場所は `~/.claude/skills/man-ja/`(個人用。リポジトリの外)。ほかの PC で使うときはこのフォルダごとコピーする。
内容を直すときは `SKILL.md`(手順)と `fix_man_ja.py`(スクリプト)を編集する。
Sphinx の `conf.py` に組み込んだ手直しの処理は `fix_man_ja.py` と同じ動きなので、片方を直したらもう片方も直す。

## 症状

日本語の man ページを `man` で表示すると、

- 行の中の空白が大きく広がる(例: `eyedrop          は、目薬の…`)
- 日本語の途中で改行されず、行がはみ出す
- `troff: warning: cannot adjust line` / `cannot break line` が画面に出る

原因: groff は日本語の文字の間を改行できる位置と見なさず、両端そろえ(既定 `.ad b`)のために
数少ない空白を広げる。man マクロは段落ごとに行そろえを既定(文字列 `AD`、既定は `b`)に戻す。

## 対策(roff の手直し)

1. `.TH` の直後に次を入れる
   - `.ds AD l` … man マクロが段落ごとに戻す既定を左寄せに(これが無いと `.ad l` だけでは警告が残る)
   - `.ad l` … 左寄せ
   - `.nh` … ハイフネーションなし
2. 日本語の文字(U+3000–30FF、U+3400–9FFF、U+FF00–FFEF)の直後に、改行してよい印 `\:` を入れる。ただし
   - 次の文字が句読点・閉じ括弧・長音(`、。,.)」』】〕!?ー` と全角の `），．！？`)のときは入れない(行頭に「、」が来るのを防ぐ)
   - 行末には入れない(警告の原因になる)
   - マクロの行(`.` や `'` で始まる行)と整形済みの範囲(`.nf` 〜 `.fi`、コード例など)には入れない

この手直しはスクリプト `fix_man_ja.py`(このスキルと同じフォルダ)にある。

```sh
~/.claude/skills/man-ja/fix_man_ja.py page.1            # その場で書き換え
~/.claude/skills/man-ja/fix_man_ja.py -o out.1 page.1   # 別のファイルへ
```

何度実行しても結果は同じ。ソース(rst など)ではなく、生成された roff に対して行う。

## Sphinx で man ページを作るときの組み込み方

`conf.py` の `build-finished` で手直しして、リポジトリの `man/` に置く(生成物はコミットして install で入れる)。
ビルドの出力先は作業用(`_build/man`)にする。拡張(sphinx_rtd_dark_mode など)が出力先に空の `_static` を作ることがあるため。

```python
import re
from pathlib import Path

_CJK = re.compile(r'([\u3000-\u30ff\u3400-\u9fff\uff00-\uffef])'
                  r'(?![、。,.)」』】〕!?ー\uff09\uff0c\uff0e\uff01\uff1f])')
_MAN_DIR = Path(__file__).resolve().parent.parent / 'man'


def _fix_man_for_japanese(text: str) -> str:
    out = []
    fill = True
    for line in text.split('\n'):
        if line.startswith('.TH '):
            out += [line, '.ds AD l', '.ad l', '.nh']
            continue
        if line.startswith('.nf'):
            fill = False
        elif line.startswith('.fi'):
            fill = True
        if fill and not line.startswith(('.', "'")):
            line = _CJK.sub(r'\1\\:', line)
            if line.endswith('\\:'):
                line = line[:-2]
        out.append(line)
    return '\n'.join(out)


def _install_man(app, exception):
    if exception or app.builder.name != 'man':
        return
    _MAN_DIR.mkdir(exist_ok=True)
    for page in Path(app.outdir).glob('*.[1-9]'):
        (_MAN_DIR / page.name).write_text(
            _fix_man_for_japanese(page.read_text(encoding='utf-8')),
            encoding='utf-8')


def setup(app):
    app.connect('build-finished', _install_man)


man_pages = [('コマンド名', 'コマンド名', '一行の説明', [author], 1)]
```

```sh
sphinx-build -b man -d <doctrees> <srcdir> <srcdir>/_build/man   # → man/コマンド名.1
```

man ページのソース(rst)は HTML のドキュメントと共用できる(toctree に入れれば両方に出る)。
見出しは man の慣例に合わせて「書式・説明・オプション・…・環境変数・ファイル・例・関連項目」。
NAME 節は `man_pages` の説明から自動で作られる。コマンドの書式は行ブロック(`| **cmd** [**-f** *FILE*]`)で書くと
man では `.nf` の範囲になり、そのまま1行ずつ出る。

## rst(docutils)で日本語を書くときの注意

インラインのマークアップ(` ``literal`` `、`*強調*`、`**太字**`)の終わりの直後に、
docutils が区切りと認めない文字が続くと「Inline literal start-string without end-string」の警告になり、正しく変換されない。

- だめな例: ` ``-d 7/10``(今年) `(全角の開き括弧)、` ``visit``・``next`` `(中黒は区切りと認められない)
- 直し方: 間に `\ `(エスケープした空白。表示には出ない)を入れる
  → ` ``-d 7/10``\ (今年) `、` ``visit``\ ・\ ``next`` `
- 読点「、」・句点「。」・閉じ括弧「)」は区切りとして認められるので、そのままでよい
- 一括置換で `\ ` を入れるとリテラルの内側に入ってしまいやすい。警告の出た行を見て手で直すほうが確実

## 確認

```sh
LANG=ja_JP.UTF-8 MANWIDTH=80 man -l man/コマンド名.1 2>&1 >/dev/null | wc -l   # troff の警告の数(0 が目標)
LANG=ja_JP.UTF-8 MANWIDTH=80 man -l man/コマンド名.1 2>/dev/null | col -b | less  # 見た目
LANG=ja_JP.UTF-8 MANWIDTH=80 man -l man/コマンド名.1 2>/dev/null | col -b | grep -nE '^\s+[、。)]'  # 行頭の句読点(0 件が目標)
```

幅を変えて(`MANWIDTH=80`・`90` など)何通りか確かめる。インストールした後は `man -w コマンド名` で見つかるか確認する
(`MANPATH` を設定していると、`PATH` からの自動の推測(`~/bin` → `~/share/man` など)は使われない)。
